Challenges of Quantum Computation

Quantum Computing, Mapped · part 06 of 09 · current to November 2026
TL;DR — Why don't we already have the machines page 05 needs? Because physical qubits fail roughly once every thousand operations, and the useful algorithms need billions of operations to run clean. Error correction closes that gap only below a threshold error rate, and it costs hundreds to thousands of physical qubits per logical qubit, plus expensive "magic" for T gates, plus a classical decoder that must keep pace in real time. The one thing to remember: the field's progress is measured in physical error rate p and overhead per logical qubit, not in raw qubit count.

Page 04 gave you a perfect machine: unitaries applied exactly, measurements that return honest Born-rule samples. Page 05 priced the algorithms on that machine. This page is the bill for building it out of real hardware. It is also the lens for the rest of the map: once you know what a code distance, a threshold and a post-selection rate are, the announcements on pages 07 and 08 read very differently.

Noise: continuous errors on a fragile state

A classical bit is a voltage well separated from the other voltage; small disturbances get snapped back by every gate. A qubit has no such restoring force. Its state α|0⟩ + β|1⟩ lives on a continuum, and every unwanted interaction with the environment nudges it.

Two textbook time constants describe how fast an idle qubit forgets:

  • T1 (relaxation) — how long before |1⟩ decays to |0⟩ by losing energy to the environment. An amplitude-damping process.
  • T2 (dephasing) — how long the relative phase φ between |0⟩ and |1⟩ survives. Random drifts in the qubit frequency smear φ until the superposition behaves like a coin flip. Always T2 ≤ 2·T1.

What matters is the ratio of coherence time to gate time. Transmons cohere for tens to hundreds of microseconds and gate in tens of nanoseconds; trapped ions cohere for seconds but gate far slower. Both land in the same regime: a two-qubit gate error p around 10⁻³, sometimes a bit better.

Gates add their own errors: a pulse meant to rotate by π rotates by π + ε, neighbours crosstalk, transmons leak into |2⟩, atoms fall out of traps, and measurement misreads.

"Errors are continuous" sounded fatal in the 1990s: infinitely many possible errors, and you cannot look at the state without collapsing it. The resolution is error discretisation. Any single-qubit error operator can be written as

E = e₀·I + e₁·X + e₂·Y + e₃·Z

because the Paulis span all 2×2 matrices. If you measure carefully chosen parities of several qubits rather than the qubits themselves, that measurement projects the continuous error onto one of the discrete Pauli branches, tells you which one, and leaves the encoded information untouched. Correct the Pauli and you have corrected the continuous error. Bit flips (X) and phase flips (Z) are all you need to handle; Y = iXZ is both.

The threshold theorem: physical vs logical error

Precise vocabulary first, because announcements blur it.

  • Physical error rate p — the probability that one physical operation (a gate, an idle step, a measurement) introduces an error. Usually quoted as the two-qubit gate error, the worst of the lot.
  • Logical qubit — one qubit's worth of information spread across many physical qubits by a code, so that no small set of physical failures can change it.
  • Logical error rate p_L — the probability that the encoded information is corrupted per round of error correction (for memory) or per logical gate. Which one is quoted matters; memory is the easy case.
  • Code distance d — the smallest number of physical errors that can silently turn one valid codeword into another. A distance-d code corrects up to ⌊(d−1)/2⌋ errors and detects up to d−1.

The threshold theorem (Aharonov and Ben-Or; Knill, Laflamme and Zurek; Kitaev, all in the late 1990s) says: if every physical component fails independently with probability below some constant p_th, then you can make the logical error rate as small as you like with only polylogarithmic overhead, by growing the code. Below threshold, adding qubits helps. Above it, adding qubits adds more ways to fail than the code can catch, and a bigger code is worse.

Intuition from the classical repetition code: store three copies and majority-vote. It fails only if two flip, probability about 3p², and with d copies the failure rate scales like p^((d+1)/2). Quantum codes keep that exponent but must catch both X and Z errors with noisy measurements, which pushes the threshold from tens of percent down to about one percent.

The surface code, and what it costs

The surface code is the workhorse: its threshold is high (about 1%) and it needs only nearest-neighbour interactions on a 2D grid, exactly what a superconducting chip offers.

Lay out d² data qubits on a d × d grid. Between them sit d² − 1 measure qubits. Each measure qubit repeatedly checks one stabilizer: the product XXXX or ZZZZ of its (up to four) data-qubit neighbours. A valid codeword is a +1 eigenstate of every stabilizer, so in the absence of errors every check returns +1. An X error on one data qubit flips the neighbouring Z-type checks; a Z error flips the X-type checks. The pattern of flipped checks is the syndrome. Crucially, the checks commute with the logical operators, so measuring them reveals where errors are without revealing the encoded state.

One round (or cycle) of syndrome extraction is: entangle each measure qubit with its four neighbours by four CNOT or CZ gates, measure the measure qubits, reset them. Rounds repeat about once a microsecond on superconducting hardware. Measurements are noisy too, so you compare syndromes across rounds: what the decoder actually sees is a 3D spacetime pattern of "detection events" where a check changed value.

The decoder is a classical algorithm that takes those events and infers the most likely set of physical errors. For the surface code, errors create pairs of detection events at the ends of error chains, so decoding is essentially minimum-weight perfect matching on a graph: pair up the events with the shortest total chain. A logical error happens only when the real errors form a chain stretching across the whole patch, which needs about d/2 faults to fool the matcher. That gives the scaling used throughout this site:

p_L ≈ 0.1 · (p / p_th)^((d+1)/2) p_th ≈ 0.01 physical qubits per patch = d² + (d² − 1) = 2d² − 1

Here p_L is per logical qubit per round, and the factor 0.1 is an empirical prefactor. Define the suppression factor Λ = p_th / p: every time d grows by 2, p_L drops by a factor Λ. At p = 10⁻³, Λ = 10, and each step of distance buys one decimal digit of reliability. At p = 5×10⁻³, Λ = 2 and you need twice as many distance steps per digit, each step costing quadratically more qubits.

Real hardware is measured against this. Google's Willow chip ran distance 3, 5 and 7 surface-code memories and saw logical error fall by Λ ≈ 2.14 per step, with the distance-7 logical qubit outliving the best physical qubit by about 2.4× (Google Quantum AI, Nature 2024 peer-reviewed). A distance-7 patch is 2·49 − 1 = 97 qubits, which is why that experiment fits on a 105-qubit chip. A 2026 follow-up, with a reinforcement-learning controller retuning the chip during error correction, reached 7.72×10⁻⁴ logical error per cycle at distance 7 (Nature, July 2026 peer-reviewed). Λ ≈ 2 is "below threshold", genuinely, but only just: the model above says you want Λ near 10 before the overhead becomes comfortable.

Worked example

Suppose p = 10⁻³ and an algorithm needs every logical qubit to survive with p_L ≈ 10⁻¹² per round (a thousand logical qubits over a billion rounds, give or take, with a ~10% chance of any failure in the run).

p_L(d) = 0.1 · (10⁻³ / 10⁻²)^((d+1)/2) = 10^(−1 − (d+1)/2) want ≤ 10⁻¹² ⇒ (d+1)/2 ≥ 11 ⇒ d = 21 qubits per logical = 2·21² − 1 = 881 ≈ 900

Nine hundred physical qubits for one good one, just to store it; routing space and the factories below typically multiply the total by a small factor.

What to try. The default "Starling-class run" (200 logical qubits, 10⁸ rounds, p = 10⁻³) lands at d = 21, 881 physical per logical, about 176k physical qubits. Click "RSA-2048-class run" (~1,400 logical qubits, ~4×10¹¹ rounds, which is about five days at 1 µs per round): d = 29, 1,681 per logical, about 2.4M physical. Gidney's 2025 estimate does the same job with under a million qubits (arXiv 2505.15917 preprint) by using yoked surface codes for idle storage and magic-state cultivation, which tells you how much engineering lives outside this plain model. Now click "Better hardware": the same run at p = 10⁻⁴ needs only d = 15, 449 per logical, about 630k. A tenfold better physical qubit cuts the machine almost fourfold. Finally drag p right, toward 1%: watch Λ approach 1 and d explode, until the tool tells you no distance works. That cliff is the threshold.

Magic states: the cost of the T gate

The surface code makes Clifford operations (H, S, CNOT, Pauli measurements) cheap and fault tolerant, mostly by moving patch boundaries around ("lattice surgery"). But page 04's Gottesman–Knill theorem says Cliffords alone are classically simulable. You need a non-Clifford gate, normally T, and no 2D topological code like the surface code can apply it transversally.

The standard fix is to prepare a resource state |T⟩ = T|+⟩ = (|0⟩ + e^{iπ/4}|1⟩)/√2 on the side and consume it via a short Clifford-plus-measurement gadget that applies T to your data. Preparing |T⟩ directly gives an error near p, far too noisy. Magic-state distillation (Bravyi and Kitaev, 2004) takes many noisy copies and, using only Cliffords, outputs fewer, cleaner ones. The classic 15-to-1 protocol turns 15 states of error ε into one of error about 35ε³; stack two levels to get from 10⁻³ to below 10⁻¹². The magic-state factory doing this can be larger than the algorithm's own qubits, and an algorithm's T-count becomes its main runtime cost.

Recent work shrinks this. Magic-state cultivation grows a T state inside a small code, checking it repeatedly and discarding failures, and claims T states nearly as cheap as a CNOT in qubit-rounds (Gidney, Shutty and Jones, 2024). It is one reason the RSA estimate fell from 20M qubits (2019) to under 1M (2025).

Real-time decoding and the engineering wall

Decoding is a hard real-time problem. At a microsecond per round, a distance-21 patch produces hundreds of syndrome bits per microsecond, per logical qubit. The decoder must keep up or a backlog grows without bound, and every T gadget stalls until its measurement is decoded. That puts a latency budget of order a microsecond on matching or its approximations, running on FPGAs or ASICs next to the cryostat (Battistel et al., 2023). Willow's below-threshold experiment already included real-time decoding; doing it for thousands of patches at once, with lattice surgery between them, is unsolved at scale.

Wiring and cryogenics. A transmon chip sits near 10 millikelvin in a dilution refrigerator, with a few coaxial lines per qubit running from room temperature. Fine for hundreds of qubits, not obviously for a million: heat load, cable volume and cost all scale linearly. The routes out (cryogenic CMOS control, multiplexed readout, linking fridges with microwave or optical interconnects) each carry a fidelity penalty.

Other modalities have other walls. Ions and atoms need stable lasers and optics rather than cables, but their rounds are far slower, so the same algorithm runs much longer; atoms must be reloaded mid-run; photons are lost rather than flipped. None is a physics no-go; all are years of engineering.

qLDPC codes: less overhead, harder wiring

The surface code is wasteful in a precise sense: each patch encodes one logical qubit, so overhead scales like d² per qubit. Quantum low-density parity-check (qLDPC) codes keep every check small (each involves only a few qubits) but are not restricted to a flat local grid, which lets one block encode many logical qubits at once.

IBM's "gross" code is the flagship example: a bivariate-bicycle code written [[144, 12, 12]] (144 data qubits, 12 logical qubits, distance 12), using 288 physical qubits including the check qubits, roughly a tenth of what surface-code patches would need for similar protection at p ≈ 10⁻³ (Bravyi et al., Nature 2024 peer-reviewed). IBM's fault-tolerance roadmap is built on these codes: Starling, 200 logical qubits running 100 million gates by 2029 (IBM, 2025 company claim). Applied to cryptanalysis, a 2026 architecture study puts RSA-2048 under 100,000 physical qubits with the same 10⁻³ and 1 µs assumptions as Gidney's estimate (Iceberg Quantum, 2026 preprint).

The catch is connectivity. In the gross code each qubit talks to six others and some of those links are long range, so a flat nearest-neighbour chip will not do. Superconducting designs need multi-layer couplers that reach across the chip; neutral-atom machines can physically move atoms to bring distant qubits together, as the reconfigurable 448-atom Harvard/MIT/QuEra architecture does (Nature, 2025 peer-reviewed), and trapped ions shuttle ions or use all-to-all gates. qLDPC decoders are also harder than matching, and logical gates between qubits sharing one block are awkward. You trade qubit count for wiring, decoder complexity and gate design.

Carry this away: the cost of a fault-tolerant computer is set by three numbers, not one. The physical error rate p fixes Λ; Λ and the run length fix the distance d; d and the code fix the physical qubits per logical qubit. A headline qubit count without p, d and the code is not a measurement of progress.

NISQ, error mitigation, and the loose "logical qubit"

Preskill named the current period NISQ, noisy intermediate-scale quantum: tens to a few hundred qubits, no error correction, circuits limited to roughly 1/p gates before noise wins (Preskill, 2018). Whether such machines do anything commercially useful was, and still is, an open question.

Error mitigation is the NISQ toolbox: zero-noise extrapolation (run the circuit at deliberately amplified noise and extrapolate the expectation value to zero noise) and probabilistic error cancellation (sample from a quasi-probability mix of circuits that inverts a learned noise model) (Temme, Bravyi and Gambetta, 2017). It is useful, but it is not error correction. It fixes expectation values, not individual shots, and its sampling cost grows roughly like e^(c·p·G) in the number of gates G: exponential in circuit size, so it only stretches circuits by a modest constant factor.

Now the vocabulary trap. A distance-2 code can detect one error but cannot correct it; all you can do is throw the run away. That is error detection with post-selection, and it makes results look clean while the discard rate grows exponentially with circuit size. A distance-7 code under active correction is a different object. Both get called "logical qubits" in press releases:

  • Infleqtion's 30 entangled logical qubits use ten blocks of the [[8,3,2]] code: distance 2, detection, post-selected (Infleqtion, 2026 company claim).
  • IBM and the University of Chicago's 70-logical-qubit headline rests on error detection with syndrome post-selection, not correction (arXiv 2607.25941 preprint). Page 08 tells the rest of that story.
  • Quantinuum's colour-code result on Helios is genuine correction at distances 3, 5 and 7, with Λ ≈ 12 and about 5×10⁻⁶ memory error per cycle at d = 7, using up to 37 physical qubits per logical. But that is a memory figure; the logical two-qubit gate was demonstrated at d = 5 with error about 7×10⁻⁵ (The Quantum Insider on Quantinuum's report, 2026 preprint company claim).

Each paper says what it did; the headlines compress it. When you read "N logical qubits", ask: what distance, detection or correction, what fraction of shots were discarded, memory or gates, and is it peer reviewed?

Check yourself

  1. Price a worse qubit — Redo the worked example with p = 2×10⁻³ and the same target p_L ≈ 10⁻¹². A good answer finds Λ = 5, solves 0.1·5^(−(d+1)/2) ≤ 10⁻¹² to get (d+1)/2 ≥ 16, so d = 31 (since 5¹⁵ ≈ 3×10¹⁰ falls short of 10¹¹ and 5¹⁶ ≈ 1.5×10¹¹ clears it), and notes the cost per logical jumps from 881 to 2·31² − 1 = 1,921: a 2× worse qubit costs about 2.2× the hardware.
  2. See a threshold appear code — In numpy, simulate the classical repetition code: for d ∈ {3, 5, 7, 9} and p from 0.05 to 0.6, flip each of d bits with probability p over 10⁵ trials, majority-vote, and plot the failure rate against p on log axes. A good answer shows the curves crossing at p = 0.5, larger d winning below it and losing above it, and slopes near (d+1)/2 at small p. Then explain why the quantum surface code's crossing sits near 1% instead of 50%.
  3. Read a press release — A hypothetical announcement says "50 logical qubits on 100 physical qubits." Before you believe it means 48 fault-tolerant qubits, list the questions you need answered. A good answer notes that 2 physical per logical forces a very small code (distance 2 at most for most constructions), then asks: detection or correction; post-selection rate; memory or logical gates, and which gates; how many rounds; and whether there is a peer-reviewed paper.
  4. Mitigation's bill — Probabilistic error cancellation multiplies the number of shots needed by roughly e^(2·p·G). With p = 10⁻³, how many gates G can you run before the overhead passes 10⁶? A good answer gets G ≈ ln(10⁶)/(2·10⁻³) ≈ 6,900 and contrasts that with the 10⁸–10¹² operations page 05's algorithms need.
